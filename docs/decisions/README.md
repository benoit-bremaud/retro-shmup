# Architecture Decision Records

Nygard-format ADRs, one file per decision, named `ADR-NNNN-<kebab-slug>.md`. Status changes
(superseding, deprecating) require a dedicated PR, never an edit in passing (see `CLAUDE.md`).
The design decisions these ADRs implement are fixed in the
[Game Design Document](../design/game-design-document.md), §13 and the Decision record.

| ADR | Title | Gist |
|---|---|---|
| ADR-0001 | Rendering | Native Canvas 2D behind a minimal `RenderPort`; 240 x 320 integer-scaled; no framework. |
| ADR-0002 | Timestep, determinism and performance | Fixed 60 Hz accumulator loop, render interpolation, seeded RNG, no allocation in the loop (the `Pool<T>` interface retired by ADR-0024). |
| ADR-0003 | Architecture and tests | Composition + patterns, ports for browser APIs, UML-first; test pyramid with headless level simulation (decision 2 partially superseded by ADR-0019, the boss sentence of decision 1 by ADR-0022). |
| ADR-0004 | Delivery | Cloudflare Pages PR previews (staging) and `main` production; itch.io releases via butler on tag push. |
| ADR-0005 | Licensing | MIT for the code; assets under their own licences in `public/assets/` with `CREDITS.md`. |
| ADR-0006 | Player data | `localStorage` only, versioned key, no personal data beyond three initials; no backend in 1.0 (decisions 3 and 7 partially superseded by ADR-0021: a name of up to 8 characters and an optional country). |
| ADR-0007 | Quality gate | Local-first: husky hooks run gitleaks, lint, typecheck, tests with coverage and the local SonarQube gate before every push; CI keeps Gitleaks and a light `ci.yml` only. |
| ADR-0008 | Public hosting | One first-level subdomain per game on `benoitbremaud.fr` (own Pages project, own `_headers`); catalogue page `/jeux/` on the portfolio (decision 3 superseded by ADR-0017). |
| ADR-0009 | Input and audio contracts | Flat reusable intent frame (movement, held / pressed masks, device, tap), bindings and capture, gestures in the input adapter, audio mix control; decision 1 partially superseded by ADR-0020. |
| ADR-0010 | Presentation outside the outcome | Separate random streams, time effects in the loop, `RunPresenter`, one ordered bus per run, `DropTable` as data, HUD region. |
| ADR-0011 | Toolchain | pnpm, Vite 8, TypeScript ~6.0 (typescript-eslint support), Vitest 5, ESLint 10 strict type-checked, Prettier on code, husky hooks running `make verify`. |
| ADR-0012 | Binding shapes | Keyboard slots hold `KeyboardEvent.code`, gamepad slots hold standard-mapping indices; primary slot never empty; capture as a discriminated union. |
| ADR-0013 | Quality gate and CI after going public | Partially supersedes ADR-0007: CI table (CodeQL with TypeScript, Dependency Review, Scorecard weekly and non-blocking) and the audit exceptions of the local gate. |
| ADR-0014 | Logical screen and render regions | Partially supersedes ADR-0001 (off-screen size, scale formula, field-only shake at draw time): 480 × 320 logical screen (field centred, 120 px HUD bands), integer scale in device pixels, domain `dt` in seconds. |
| ADR-0015 | Device input and the portrait screen | Partially supersedes ADR-0014 (decision 6; decisions 1 to 4 now landscape-only): portrait screen chosen when it fits with the larger integer scale, `RenderPort.layout()`, `DeviceInput` as a façade with injected browser objects, devices combined, gamepad polling, Pointer Events and gestures, default bindings; decisions 5 and 8 partially superseded by ADR-0020. |
| ADR-0016 | Deploy every playable build | Partially supersedes ADR-0008 (decision 5): the Pages project is created at the first playable build; every merge to `main` deploys; the portfolio card says the game is in development. |
| ADR-0017 | Games catalogue in the projects page | Partially supersedes ADR-0008 (decision 3) and the catalogue address of ADR-0016: the games catalogue is the "Jeux" category of `benoitbremaud.fr/projets/`; each card shows status, play and code links; the thumbnail waits for sprites. |
| ADR-0018 | Device input after the enemies brick | Partially supersedes ADR-0015 (decisions 1, 4, 5, 7, 8, 9 and the renderer `resize` consequence): the domain hit-tests the touch pause button with `RenderPort.layout()`; `hud.ts` draws the whole HUD; HUD taps win, left click taps, right click bombs on the field; `Start` is also `Confirm`, fixed roles kept after a remap; the mouse takes the ship only by a move on the field; pointer targets floored, stick rounded toward zero; page-level listeners, cached canvas rectangle, layout change pauses; sequence-ordered arbitration; decision 2 partially superseded by ADR-0020. |
| ADR-0019 | Player kit — seeded randomness, damage in tenths, weapons as data | Partially supersedes ADR-0003 (decision 2, weapon Strategy) and ADR-0002 (decision 6, pickup pool log); refines ADR-0002 decision 5 (no draw for the sway) and ADR-0014 decision 7 (`main.ts` draws the run seed): `Run({ script, seed })` owns a `SeededRandom`, seed from the composition root; HP and damage in tenths of a shot; `WEAPONS` tables and one `fire()`; pierce memory, pickup collision pass, `shieldBroken`; pooled `Pickup` and `Formation`; pickup, bomb, shield and formation events; `collect(): number`; `DifficultyProfile` subset; bomb at step slot (3); Carrier data and `CrossMovement`; palette and HUD layout additions. |
| ADR-0020 | Pointer fire — held button and steering finger | Partially supersedes ADR-0009 (decision 1, always-held pointer `Fire`), ADR-0015 (decisions 5 and 8, the always-on `Fire` mask and the left button) and ADR-0018 (decision 2, the left button taps and now also holds `Fire` from a press on the field): the mouse fires while the left button is held after a press on the field, touch while a finger steers; the held pointer `Fire` combines like any button; the always-on fire becomes an autofire option (options brick), the only `Fire` the arbitration masks. |
| ADR-0021 | Hall of fame entry — name and optional country | Partially supersedes ADR-0006 (decision 3, the 3-character `initials`; decision 7, "no personal data beyond three initials"; the matching review item): `name` of 1–8 characters (A–Z, 0–9, space, trimmed, not all spaces) or `???` when skipped, optional `country` checked against an ISO 3166-1 alpha-2 allowlist; the language-region preselection stored only on confirmation; nothing sent; a failing entry is dropped; first schema `version: 1` with no migration since none shipped; fonts gain 0–9 and `?`. |
| ADR-0022 | Level brick — strategy factories, the boss outside the enemy pool, a one-level slice | Partially supersedes ADR-0003 (decision 1, "A `Boss` is an `Enemy`"): strategies built once by factories from tuning data (`enterHoldLeave`, `ringAttack`, `fanAttack`, `sequenceAttack`…), shared by the Gunner and the Heavy; `Body.volleys`; `SizeTier.LARGE`; one preallocated `Boss` body in `World` with a state enum and `BossDefinition` / `BossPhaseSpec` data; `LevelScript.warningAt` and `boss` required, `loopAt` removed, `startBoss` from the director; `HitRules.damageBoss`; boss and level events; `LEVEL_CLEARED` / `RUN_CLEARED` outcomes over a level list; `LevelTally` as a subscriber; the boss snapshot, HP bar, WARNING and slow-motion switch; `Results` and the slice ending `RUN_CLEARED` → `Results` → `Title`; PRs F-0 to F-3 (decisions 1, 2, 3 and 10 partially superseded by ADR-0023). |
| ADR-0023 | Boss fight — one timer per attack, movement age, boss bonus tuning, three PRs | Partially supersedes ADR-0022 (decisions 1, 2, 3, 10): every pattern is a `fire` (one volley for a count) and a `tick` (the timed wrapper); `sequenceAttack` takes groups, the volley index is the count, so the Cruiser's phase 2 is `sequenceAttack([[ring], [ring, triple]], 1.5)` with no `parallelAttack`; `Body.age` = steps since the current movement began, restarted by the boss at each phase change with a pending phase swapped when it passes x 120; `BossDefinition` without a bonus, `BossTuning` holds 10 000 + 100 per second; the boss view gains `stateSteps`; F-2 in three PRs (domain with grey boss and interim banner, HUD, game feel) and a `Run` size checkpoint for `RunRules`. |
| ADR-0024 | Retire the `Pool<T>` interface | Partially supersedes ADR-0002 (the `Pool<T>` line of its minimal interfaces): `FixedPool<T>` is the pool contract; an interface returns only with a second implementation. |
| ADR-0025 | Versioning policy | Refines ADR-0004: SemVer 2.0.0 over a declared public surface (the save document and the URL parameters, not balance); bump table, `v0.1.0` after the rebalance, manual signed tags and a release PR, the version shown outside the canvas as `v<version>+<short commit>`; release-please rejected. |
| ADR-0026 | The smoke test in three engines, with a hall-of-fame persistence check | Refines ADR-0003 (decision 7) and ADR-0007: one smoke file run in Chromium, Firefox and WebKit, local only; a seed → reload → options change → reload step proves the saved names survive; the CDP frame-time measure is Chromium-only; `vite preview` started directly so no server is left on :4173. |
| ADR-0027 | Feedback through an external form link, and the country saved once | Clarifies ADR-0006 (opening an external page in a new tab at the player's request is a navigation, not a game network call) and amends ADR-0021 decision 4 (the country chosen once at the first *Play*, saved in the options, copied into each entry); a Tally form with rotating question sets picked by a `set` parameter, allowlisted context parameters, the gesture rule, save kept at version 2; `mailto:`, local export and an HTML form rejected. |
